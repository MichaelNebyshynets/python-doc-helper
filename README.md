# Ассистент по документации PyTorch (RAG)

Локальный помощник, который отвечает на вопросы по документации PyTorch на русском и английском,
ссылается на найденные фрагменты и отказывается отвечать, если ответа в документации нет.
Всё работает на своём компьютере: модели запускает Ollama, в облако ничего не уходит.

Проект сделан как итоговая работа по курсу машинного обучения.

## Возможности
- Корпус из 6705 фрагментов: исходники документации (`.md`) и docstring'и из установленного пакета `torch`.
- Поиск по смыслу: эмбеддинги `bge-m3` в векторной базе Chroma; необязательный гибрид с BM25.
- Отказ, когда ответа нет: проверка имён `torch.*` и порог реранкера `bge-reranker-v2-m3`.
- Точное имя из вопроса (`torch.nn.Linear`) закрепляет страницу этого имени в контексте.
- Необязательный граф связей между функциями (по ссылкам из docstring'ов) расширяет контекст.
- Ответ строит `qwen2.5:7b` только по найденным фрагментам, с ссылками `[n]`; номера проверяются кодом.
- Интерфейсы: консоль и веб-чат (React + FastAPI) с потоковым выводом.

## Как это работает
```
вопрос → проверка имён torch.* → закрепление страницы по имени → поиск в Chroma (30 кандидатов)
       → реранкер решает, отвечать ли → контекст (+ соседи по графу) → qwen2.5:7b → ответ со ссылками [n]
```

## Требования
- Python 3.10+, [Ollama](https://ollama.com), Docker (Docker Desktop), Node.js 18+ (только для веб-чата).
- Проверялось на MacBook с Apple Silicon и 16 ГБ памяти.

## Установка и запуск
```bash
# 1. модели
ollama pull bge-m3
ollama pull qwen2.5:7b

# 2. Python-зависимости
pip install -r requirements.txt

# 3. векторная база Chroma (сервер в Docker, порт 8001, данные в chroma_data/)
docker compose up -d
python rag.py index        # заполнить базу из data/chunks_full.json и data/emb.npy, около 10 секунд
```

### Консоль
```bash
python rag.py ask "Как работает torch.nn.Linear?" --graph
python rag.py eval         # проверка поиска и отказов на eval*.json
python rag.py graph        # пересобрать граф связей
```

### Веб-чат
Режим разработки (два терминала):
```bash
uvicorn api:app --port 8000
cd frontend && npm install && npm run dev       # http://localhost:5173
```
Одним сервером:
```bash
cd frontend && npm install && npm run build && cd ..
uvicorn api:app --port 8000                     # http://localhost:8000
```

API: `GET /api/config`, `POST /api/ask` (поток SSE: события `sources`, `token`, `refusal`, `done`, `error`).
Тест разбора потока: `cd frontend && npm test`.

Порты: Ollama 11434, Chroma 8001, API 8000, Vite 5173. Остановить Chroma: `docker compose down` (данные сохраняются).

## Результаты
Прогон `python rag.py eval`:

| набор | нужный фрагмент в контексте | отказы на вопросы без ответа |
|---|---|---|
| основной, 48 вопросов | 33 из 34 | 14 из 14 |
| отложенный, 10 вопросов | 4 из 5 | 5 из 5 |

Граф связей на 14 специальных вопросах: покрытие 0.25 без графа и 0.86 с графом.
Наборы небольшие и составлены с помощью ИИ-ассистента, поэтому различия порядка 0.03–0.05 не значимы.
Слабое место: вопросы без точного имени функции («how to save and load a model»).
Все таблицы, методика и ограничения: [RESULTS.md](RESULTS.md).

## Структура
| путь | что это |
|---|---|
| `rag.py` | ядро: Chroma, поиск, отказы, граф, генерация, проверка, консольные команды |
| `api.py` | FastAPI-бэкенд для веб-чата |
| `frontend/` | React + Vite чат |
| `docker-compose.yml` | сервер Chroma |
| `data/` | `chunks_full.json` и `emb.npy` (корпус и эмбеддинги, из них заполняется Chroma), `docs.json` (docstring'и), `graph.json` (граф), `eval*.json` (тестовые вопросы), `chunks.json` (промежуточная версия корпуса) |
| `notebooks/` | ноутбуки: `01_exploration` (эксперименты), `corpus_clean` (сборка корпуса), `02_search` (эмбеддинги, поиск, метрики), `03_graph` (граф) |
| `RESULTS.md` | результаты и выводы |
| `docs/PROJECT_GUIDE.pdf` | подробное руководство по коду |

## Пересборка корпуса
Корпус собирается в `notebooks/corpus_clean.ipynb` из `docs/source` клона [pytorch/pytorch](https://github.com/pytorch/pytorch)
(по умолчанию `~/pytorch/docs/source`, путь задаётся переменной `DOCS`) и docstring'ов установленного `torch`.
Эмбеддинги считаются в `notebooks/02_search.ipynb`. Ноутбуки запускай из папки `notebooks/` (так открывает Jupyter), они читают и пишут файлы в `../data/`. После пересборки: `python rag.py index` и `python rag.py graph`.
Версии документации и установленного `torch` могут слегка расходиться.
